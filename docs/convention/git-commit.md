# 🛠 Git Commit Convention

이 프로젝트는 **Semantic Commit Message**와 **Conventional Commits**를 기반으로 한 커밋 규칙을 따릅니다. 협업 시 가독성을 높이고 히스토리 관리를 용이하게 하기 위해 아래 규칙을 준수해 주세요.

---

## 🚀 커밋 전 필수 작업

> [!IMPORTANT]
> **커밋을 진행하기 전에 반드시 원격 저장소(`origin`)로부터 최신 코드를 `pull` 받아야 합니다.**
> 로컬 변경 사항과 원격 저장소의 충돌을 미연에 방지하고 최신 히스토리를 유지하기 위함입니다.
>
> ```bash
> git pull origin <브랜치명>
> ```

---

## 🏗 메시지 구조

기본적으로 제목은 필수이며, 본문과 푸터는 선택 사항입니다.

```text
{이모지} {타입}: {제목} (#이슈번호)

{본문 - 무엇을, 왜 했는지 설명 (선택)}

{푸터 - 이슈 트래킹 번호 (선택)}
```

---

## 🏷 타입 및 이모지 (Type & Emoji)

| 이모지 | 타입         | 설명                               | 예시                                            |
| :----- | :----------- | :--------------------------------- | :---------------------------------------------- |
| ✨     | **feat**     | 새로운 기능 추가                   | `✨ feat: 비회원 주문조회 페이지 작성`          |
| 🚑     | **fix**      | 버그 수정 (긴급/기능 오류)         | `🚑 fix: 빌드 오류 수정`                        |
| 🔨     | **refactor** | 코드 리팩토링                      | `🔨 refactor: 비회원 마이페이지 접근 로직 개선` |
| 💅     | **style**    | UI 스타일 수정 및 디자인 변경      | `💅 style: depth4 카테고리 스타일 수정`         |
| 📦     | **package**  | 패키지(의존성) 추가, 수정, 삭제    | `📦 package: nextjs 16.2.6 업데이트`            |
| 🔧     | **chore**    | 설정 변경, 단순한 수정, 기타 작업  | `🔧 chore: 린트 규칙 업데이트`                  |
| 📝     | **docs**     | 문서 수정 (README, 커밋 컨벤션 등) | `📝 docs: 커밋 컨벤션 문서 다듬기`              |
| ✅     | **test**     | 테스트 추가 및 수정                | `✅ test: 주문 API 유닛 테스트 추가`            |
| 🎉     | **init**     | 프로젝트 시작 (Initial Commit)     | `🎉 init: 프로젝트 초기화`                      |

## 📝 작성 규칙

### 1. 제목 (Subject)

- **명령형 현재 시제**를 사용합니다. (`추가함` (X) → `추가` (O), `Fixed` (X) → `Fix` (O))
- **한글 사용 권장**: 프로젝트 특성상 제목에는 한글을 사용하여 명확하게 전달합니다.
- **50자 이내**: 핵심 내용만 간결하게 작성합니다.
- 끝에 마침표(`.`)를 찍지 않습니다.

### 2. 본문 (Body)

- 어떻게(How)보다는 **무엇을(What)**, **왜(Why)** 변경했는지에 집중하여 작성합니다.
- 제목과 본문 사이에는 **한 줄의 공백**이 필요합니다.
- 한 줄의 길이는 **72자 이내**로 제한하는 것을 권장합니다.
- 본문의 각 변경 사항은 문장 앞에 `- `를 붙여 목록 형태로 작성합니다.
- 변경 사항은 항목별로 줄바꿈하여 구분하되, 항목 사이에 빈 줄을 추가하지 않습니다.
- 문장은 과거형(`~했습니다`) 대신 간결한 명사형 또는 동작형(`~추가`, `~수정`, `~삭제`, `~개선`)으로 작성합니다.

### 3. 푸터 (Footer)

- 이슈 트래킹 번호를 남길 때 사용합니다.
- 형식: `Resolves: #번호` 또는 `(#번호)`를 제목 뒤에 붙입니다.
- 두레이 등 외부 프로젝트 번호를 병기할 경우 `#프로젝트명/번호` 형식을 사용합니다.
  - 예: `(#더본-업무요청/123)`

---

## 💡 예시 (Examples)

> [!TIP]
> 실제 프로젝트 커밋 로그에서 발췌한 좋은 예시들입니다.

- `✨ feat: 유튜브 영상인 경우 레시피 썸네일 상단 고정`
- `🔨 refactor: footer component 리팩토링`
- `🚑 fix: 쿠폰 모달 내 쿠폰 적용/실패 및 오류 메시지 처리`
- `💅 style: 상품 카드 랭크 스타일 수정 (#56)`
