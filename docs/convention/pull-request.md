# PR(Pull Request) Convention

협업 시 코드 리뷰와 히스토리 관리를 용이하게 하기 위한 PR 작성 규칙입니다.

---

## 🏗 제목 (Title)

- **이모지, 타입 접두어(`feat:`, `fix:` 등) 사용 금지** — 커밋 메시지와 다르게 PR 제목은 일반 문장으로 작성합니다.
- 한글 사용 권장, 핵심 내용만 간결하게 작성합니다.
- 작업한 기능/수정 내용을 명확하게 표현합니다.

```text
# 올바른 예시
휴면회원 처리 기능 추가 및 로그인 FSD-lite 리팩토링
비회원 주문 조회 페이지 추가
장바구니 수량 초과 오류 수정

# 잘못된 예시
✨ feat: 휴면회원 처리 기능 추가
fix: 장바구니 버그 수정
```

---

## 📝 본문 (Description)

PR 본문은 저장소 루트의 `PULL_REQUEST_TEMPLATE.md` 섹션 순서와 형식에 맞춰 작성합니다. 해당 내용이 없는 항목도 비워두지 말고 `없음` 또는 `해당 없음`처럼 명시합니다.

작업 내용, 변경 이유, 주요 결정 사항은 아래 항목을 기준으로 작성하는 것을 권장합니다.

- **작업 내용**: 무엇을 했는지 요약
- **변경 사항**: 파일/컴포넌트 단위로 구체적으로 나열
- **테스트**: 추가된 테스트 케이스가 있다면 명시
- **참고 사항**: 리뷰어가 알아야 할 배경, 제약 조건, 후속 작업 등

---

## 🔗 브랜치 규칙

- **base 브랜치**: 특별한 사유가 없으면 `dev`로 설정합니다.
- **head 브랜치 네이밍**: `feature/기능명`, `fix/버그명` 형태를 사용합니다.

---

## ✅ PR 생성 전 체크리스트

- [ ] 불필요한 파일(디버그 로그, 주석 처리된 코드 등)이 포함되지 않았는가
- [ ] 관련 없는 변경 사항이 같이 올라가지 않았는가
- [ ] 빌드가 통과하는가 (`pnpm build` — `next build --webpack`)
- [ ] 추가한 테스트가 통과하는가
